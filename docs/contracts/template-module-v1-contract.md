# Interface Contract: Template Module v1

## Summary and Purpose

- Owner: Core template and marketplace services; consumers are PowerShell users and `IPowerShellModuleClient`.
- Compatibility version: v1. Every listed cmdlet calls exactly one closed Bridge route. `Apply-DistroNexusTemplate` is removed from `DistroNexus.psd1`; it is not retained as an ambiguous compatibility wrapper.
- Serialization: Bridge request records use required members, reject unmapped JSON members, and use `Template.*` redacted errors. No record contains a product path, script content, executable, command line, raw archive, or arbitrary route.

WPF receives only typed display/result records through the client. `Content` is UTF-8 text capped at 1 MiB; variable maps contain at most 64 entries with key/value limits of 128/4096 UTF-8 bytes; all response lists contain at most 500 entries and output/message fields at most 16 KiB.

## Apply, Recovery, and Durable State

`RecoveryOfferDisplay` exactly mirrors the current Core `RecoveryOffer`: `(bool IsAvailable, string InstanceName, RecoveryOfferReason Reason, string MessageKey)`. The only executable choice is `DeclineRecoveryOffer=true`. A first preview with an available offer and `DeclineRecoveryOffer=false` returns `RequiresRecoveryDecline=true`, no preview token, and `Template.RecoveryDeclineRequired`; WPF then either ends the flow (the current “pause so the user can create a recovery point” behavior) or, after its explicit decline confirmation, requests a new preview with `DeclineRecoveryOffer=true`. The grant and history bind/record offer availability, instance, reason, message key and the decline decision. This slice intentionally does not claim that an existing offer is selected, created, or applied.

`TemplateApplyGrantRecord` is DPAPI `CurrentUser` protected and atomically single-consumed: `(SchemaVersion, Sid, InstanceName, TemplateId, TemplateVersion, SourceUrl, ManifestDigest, ArtifactSha256, ArtifactRootDigest, ExecutableFilesDigest, VariablesDigest, CapabilitiesDigest, RecoveryAvailability, RecoveryInstanceName, RecoveryReason, RecoveryMessageKey, RecoveryDeclined, ExpiresAt)`. Preview tokens are 32-byte opaque values, live for five minutes, and cannot be replayed.

`TemplateApplyOperationRecord` is persisted under `%LOCALAPPDATA%\\DistroNexus\\template-operations` and contains `(SchemaVersion, OperationId, Sid, GrantFingerprint, InstanceName, TemplateId, RecoveryDeclined, State, CreatedAt, WorkerLaunchDeadlineAt, StartedAt, UpdatedAt, CompletedScripts, TotalScripts, CurrentScript, Message, ErrorCode, ExecutedScripts, CancelRequested, WorkerStartedAt, WorkerPid, PendingScript)`. States are `Queued`, `Running`, `Succeeded`, `Failed`, `Cancelled`, and `Interrupted`; only the final four are terminal. A per-operation lock serializes state changes. `PendingScript` is either absent or `TemplatePendingScriptRecord(int Ordinal, TemplateScriptType Type, string StagedFileSha256, TemplatePendingScriptState State, string AttemptId, DateTimeOffset PreparedAt, DateTimeOffset? ClaimedAt, int? ChildProcessId, DateTimeOffset? ChildStartedAt)`, where its state is `Prepared` or `Claimed`.

The worker additionally holds `%LOCALAPPDATA%\\DistroNexus\\template-operations\\<OperationId>.worker.lock` open with exclusive sharing for its complete lifetime. It acquires that lock before atomically claiming `Queued` and releases it only after the terminal record write; `WorkerPid` is diagnostic only, never liveness authority. Bridge records a short `WorkerLaunchDeadlineAt` before launch and records `WorkerStartedAt` only after process start. Status/cancel/start recovery tries to acquire the worker lock: a `Running` record whose lock is acquirable becomes `Interrupted` with `Template.WorkerInterrupted`; a `Queued` record whose deadline has passed and whose lock is acquirable becomes `Failed` with `Template.WorkerStartFailed`; a held lock leaves the nonterminal record authoritative. Launch failure follows the same terminal `Failed` transition.

Before runtime invocation, `TemplateService` atomically writes `PendingScript` in `Prepared` state. Under the same lock, runtime validates it and atomically changes it to `Claimed` with a new attempt ID and timestamp before process creation. Immediately before `Process.Start`, it retakes and holds that lock through the process start and child-PID state write: if `CancelRequested` is true, it clears the claimed entry, writes terminal `Cancelled` with `Template.Cancelled`, releases the lock and starts no child; otherwise it starts the fixed child, writes its PID/start time while still holding the lock, then releases it. On normal child completion it clears `PendingScript` and appends the completed script; on an in-process start failure it records terminal `Failed`. If recovery finds an acquirable worker lock and a `Claimed` pending script—whether or not child PID was written—it marks the whole operation `Interrupted`, never re-prepares or retries the script automatically. This fail-closed rule prevents duplicate execution in the process-start/write race; the user must obtain a fresh preview to retry.

Before creating an operation and immediately before each script, Core revalidates the bound instance, template/version, normalized variables, source/manifest/artifact digests, artifact-root digest, executable-file hash list, capability digest and recovery offer fingerprint. Drift yields `Template.ProvenanceChanged`; cancellation before a script yields `Cancelled`. Cancellation during a script is cooperative: the worker marks `CancelRequested`, forwards cancellation to Core, and records only the scripts that completed; it never records rollback or candidate promotion.

Template execution does not use `IPowerShellService` or `BridgeReadOnlyPowerShellService`. The internal-only `ITemplateGrantedExecutionRuntime.ExecuteAsync(GrantedTemplateScriptPlan, CancellationToken)` accepts a plan made solely by `TemplateService` after the revalidation above; it is not a Bridge/public record. Its fields are `(OperationId, InstanceName, ScriptOrdinal, ScriptType, TimeoutSeconds, CoreStagedFile, StagedFileSha256)`.

Before process creation the runtime takes the operation-local state lock and atomically reads the same-SID `TemplateApplyOperationRecord`; it requires a nonterminal record, matching operation ID/SID/instance, `Running` state, and a persisted pending-script entry whose ordinal, type and staged-file hash match the plan. It then validates operation-root containment and file hash and consumes that pending-script entry for this attempt. A forged plan, operation-record mismatch, stale state, containment/hash mismatch or unsupported type fails closed with `Template.ExecutionPlanInvalid` and creates no process. `TemplateService` alone resolves a script file or inline content, applies the grant-bound variables, and writes the staged UTF-8 no-BOM file with atomic create under that Core-owned operation root. For marketplace material it verifies the reviewed executable hash before staging; the staged content hash is written to operation state before launch.

`FixedTemplateGrantedExecutionRuntime` constructs only two process forms: Bash is `wsl.exe --distribution <grant-bound InstanceName> --user root -- bash <Core-derived /mnt staging path>`; PowerShell is `pwsh.exe -NoLogo -NoProfile -NonInteractive -File <CoreStagedFile>`. It passes no caller-provided executable, arguments, command text, path, environment override or working directory. The only variable inputs are already normalized and grant-bound before staging. It enforces the plan timeout and forwards bounded stdout/stderr to the operation store; cancellation terminates only that fixed child process tree. Template script content remains intentionally executable approved material, never a public PowerShell command tunnel.

## Marketplace and Local-Template Semantics

`AddSourceAsync`, `SetSourceEnabledAsync`, `RemoveSourceAsync`, `DiscoverAsync`, exact `GetStatusAsync`, `DownloadArtifactAsync`, `CreateReviewGrantAsync`/`ApproveCandidateAsync`, `GetArtifactHistoryAsync`, and `RollbackAsync` are the sole Core calls behind the respectively named routes. `review` is a `ShouldProcess` mutation because it performs this fixed sequence: call `DownloadArtifactAsync(SourceId, TemplateId, ManifestDigest)`, then `CreateReviewGrantAsync(SourceId, downloadedArtifact.Sha256)`, and return the grant plus its immutable source/template/manifest/artifact/script-diff identity. `approve` accepts only that review token. Download/status/review require the exact `(SourceId, TemplateId, ManifestDigest)`. Candidate promotion remains exclusively `CompleteSuccessfulExecutionAsync` after a successful worker result.

`TemplateMarketplaceReviewGrantStore` replaces the current in-memory review-token dictionary. It persists DPAPI `CurrentUser` records under `%LOCALAPPDATA%\\DistroNexus\\template-marketplace-review-grants`, binds each record to the current SID, and consumes it through SHA-256 token filename atomic rename. `TemplateMarketplaceReviewGrantRecord` is `(SchemaVersion, Sid, Token, SourceId, NormalizedSourceUrl, TemplateId, TemplateVersion, ManifestDigest, CanonicalManifest, ArtifactSha256, ArtifactRootPath, ArtifactRootPathDigest, ExecutableFilesDigest, ScriptDiff, ScriptDiffDigest, ExpiresAt)`. `CanonicalManifest`, artifact root and full diff are protected Core-only state; the public review display exposes only version, a SHA-256 normalized-source identity, diff digest, counts, and at most 100 changed-script identifiers. Tokens are 32-byte opaque values, expire after five minutes, are deleted after consumption, and an absent, expired, mismatched, foreign-SID or malformed token yields `Template.ReviewGrantInvalid` or `Template.ReviewGrantExpired` before promotion. `CreateReviewGrantAsync` writes this record; `ApproveCandidateAsync` atomically consumes and revalidates the exact record before it materializes the candidate. The shared Bridge and worker composition use the same store root.

Local import, export and remove use the same DPAPI/SID/single-use preview-store pattern as apply. Import content is parsed/validated by Core before its preview token is issued; export returns bounded canonical content; no public request carries a filesystem location. All state or trust records retain Core-owned paths only internally.

## Errors, Retries, and Verification

Errors are stable and redacted: `Template.InvalidRequest`, `Template.GrantInvalid`, `Template.GrantExpired`, `Template.ReviewGrantInvalid`, `Template.ReviewGrantExpired`, `Template.ProvenanceChanged`, `Template.TrustRequired`, `Template.RecoveryDeclineRequired`, `Template.ExecutionPlanInvalid`, `Template.Cancelled`, `Template.WorkerStartFailed`, `Template.WorkerInterrupted`, and `Template.Failed`. Retrying any mutation requires a new applicable preview; an operation ID never authorizes execution.

Tests must name the Bridge record/cmdlet above; reject unknown fields, content/response limit violations and arbitrary routes; assert source/manifest/artifact identity, cross-process review-to-approve, review-token SID/expiry/replay/tamper rejection, apply-grant SID/expiry/replay/tamper rejection, recovery-offer/decline-required/decline-recording behavior, worker launch/interruption, cancellation before, after claim/before child start, and during each script, status/cancel races, candidate non-promotion, compatibility `Compatible`/`Incompatible` disposition, Desktop structural routing, and manifest export removal.
