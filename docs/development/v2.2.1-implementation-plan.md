## 1. Overview

v2.2.1 is a completion release for v2.2.0. All backend services are already implemented; this release wires them into the desktop GUI, completes partial implementations, and finishes infrastructure work.

**Key metrics**: 11 v2.2.0 gaps to close, 1 new dialog (`InstanceDetailDialog`), 5 new tab views, 2 new Settings sections, 9 new ViewModels, ~10 new XAML files, comprehensive unit test coverage.

## 3. Design Review Issues (Must Address)

16 issues identified in [v2.2.1-design-review.md](../specs/v2.2.1-design-review.md). The following 4 BLOCKERs must be resolved within the relevant phase:

| # | Issue | Resolution | Phase |
|---|-------|------------|-------|
| 1 | Watcher `Start()` placement creates data-race | Call `Start()` at end of `LoadDataInBackgroundAsync`, not in `InitializeAsync` | Phase 7 |
| 2 | `CompactInstanceAsync` (whatIf) returns `Task` — no reclaimable bytes | Parse reclaimable estimate from `progress.Message` callback; read file sizes via `GetInstanceDiskSizeAsync` before/after | Phase 2 |
| 3 | `IWslManagerService` has no `ShutdownAsync` | Use `IWslCliRunner.RunAsync("--shutdown", ct)` directly, or add `ShutdownWslAsync` to interface | Phase 3 |
| 4 | `ObservableCollection<T>` has no `.Filter` property | Use `ICollectionView` with `CollectionViewSource.GetDefaultView(Instances)` | Phase 6 |

Additional risks to address inline:
- Issue 5: Backup history — scan destination folder for TAR files (Phase 5)
- Issue 6: WslConfig unknown-key preservation — verify/fix in service (Phase 3)
- Issue 7: Sparse mode read via `GetInstanceConfigAsync` — pattern-match `object?` return (Phase 2)
- Issue 11: No `IDialogService` — introduce minimal interface for tab VMs (Phase 1)
- Issue 12: `WslInstanceViewModel` nested in `MainViewModel.cs` — extract first (Phase 0)
- Issue 13: `BackupSchedule.Frequency` encoding — add parse/serialize helpers (Phase 5)
- Issue 15: `WslOperationTimeoutException` hardcodes `UnknownError` — add `OperationTimeout` code (Phase 7)

## 5. Phase Summaries

### Phase 0 — Prerequisites & Refactoring {#phase-0}

Structural refactoring required before feature work begins:
- Extract `WslInstanceViewModel` from `MainViewModel.cs` to its own file
- Fix service-locator anti-pattern in `MainViewModel` (inject services via constructor)
- Introduce minimal `IDialogService` for new tab ViewModels
- Add `ShutdownWslAsync` to `IWslManagerService` (or decide on `IWslCliRunner` direct call)

### Phase 1 — Desktop Shell (Group A) {#phase-1}

Build the structural UI foundation all feature groups depend on:
- `InstanceDetailDialog` skeleton (5 empty tabs, header, footer)
- All 5 tab ViewModels (empty/stub)
- Multi-select mode infrastructure (`IsMultiSelectMode`, `IsSelected`, checkbox)
- New MoreButton menu items (Details, Compact Disk, Export Instance)
- Import Instance toolbar button
- Auto-refresh spinner placeholder

### Phase 2 — Instance Operations & Storage (Group B) {#phase-2}

Fill the Disk and Resources tabs; implement Export/Import flows:
- Disk tab: Compact flow with whatIf estimation, progress phases, result panel
- Bulk compaction via multi-select
- Export Instance flow (SaveFileDialog, progress, auto-stop prompt)
- Import Instance dialog (name validation, folder picker, progress)
- Resources tab: Sparse mode toggle, global resource display, WSL version guards

### Phase 3 — Settings Page Extensions (Group E partial) {#phase-3}

Add new sections to the Settings page:
- WSL Global Configuration editor (`.wslconfig` form, validation, Save & Restart)
- Manage Tags panel (list, rename, bulk-delete)
- Unknown INI key preservation verification/fix

### Phase 4 — Integrations & Diagnostics (Group C) {#phase-4}

Fill the Integrations and Network tabs:
- Docker Desktop integration status, toggle, install link
- Docker status icon on instance cards
- Network tab: IP address, port mapping DataGrid, proxy indicators, Copy button

### Phase 5 — Backup Scheduling (Group D) {#phase-5}

Fill the Backup tab:
- Schedule editor form (frequency, destination, retention, time)
- Backup Now button with progress
- Backup history list (folder scan)
- Remove-instance backup cleanup integration
- Startup notification verification

### Phase 6 — Dashboard Tag UI (Group E partial) {#phase-6}

Dashboard-level tag features:
- Tag chips on instance cards
- Inline +Tag popover and ×Remove
- Tag filter bar above instance list
- Group by Tag toggle
- `ICollectionView` integration for filtering/grouping

### Phase 7 — Platform Quality & Completion (Group F) {#phase-7}

Cross-cutting quality work:
- E-07: Wire `WslEventWatcher.Start()`, verify debounce, add auto-refresh indicator
- E-08: Audit and complete PowerShell service decoupling (Phase 3 registry)
- E-09: Unified error code rollout (services, ViewModels, NLog, PowerShell cmdlets)
- Add `OperationTimeout` error code
- Update `error-codes.md`
- All new resource strings in `Resources.resx` (en-US + zh-CN)
- Unit tests for all new ViewModels and service changes
- Manual walkthrough validation
