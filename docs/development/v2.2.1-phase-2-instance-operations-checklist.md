## Tasks

### P2-1: Implement Disk Tab — Compact Disk Flow

**Req**: B-01-1 through B-01-6, Design Review #2

#### P2-1a: Disk Tab UI (`DiskTabView.xaml`)

- [ ] Display VHDX path (from `WslInstanceViewModel.VhdxPath` or equivalent)
- [ ] Display current disk size
- [ ] "Compact Disk…" button
- [ ] Progress area: phase text label + indeterminate `ProgressRing` (hidden by default)
- [ ] Result panel: before/after sizes (hidden by default)
- [ ] For WSL v1 instances: hide all controls, show "Disk compaction requires WSL v2" message (UX-06)

#### P2-1b: Disk Tab ViewModel (`DiskTabViewModel.cs`)

- [ ] `InitializeAsync()`: load current disk info
- [ ] `CompactDiskCommand` implementation:
  1. **whatIf phase**: call `CompactInstanceAsync(name, whatIfProgress, whatIf: true, ct)`
     - Parse reclaimable estimate from `progress.Message` callback (look for size pattern)
  2. **Confirm dialog**: show estimated reclaim + auto-stop warning (UX-03)
  3. **Compaction phase**:
     - Record `beforeSize` via `GetInstanceDiskSizeAsync`
     - Set `IsBusy = true` on instance (UX-01)
     - Call `CompactInstanceAsync(name, progress, whatIf: false, ct)` with phase text callback
     - Phase labels: "Stopping instance…", "Trimming blocks…", "Compacting VHDX…", "Restarting instance…"
  4. **Result**: read `afterSize` via `GetInstanceDiskSizeAsync`, show before/after panel
  5. **Error**: catch `WslException`/`WslOperationException`, show via `IDialogService` + `FormatAlertMessage` (UX-05)
  6. Set `IsBusy = false` in finally block
- [ ] Handle cancellation gracefully

**Acceptance** (B-01):
- [ ] VHDX file size is smaller after compaction than before
- [ ] Instance data is intact after compaction
- [ ] Error dialog shows error code on failure

### P2-2: Implement Bulk Compaction

**Req**: B-01-7, B-01-8

- [ ] Implement `CompactSelectedCommand` on `MainViewModel`:
  1. Collect `Instances.Where(i => i.IsSelected && i.IsWslV2).ToList()`
  2. Create `CancellationTokenSource` for user cancellation
  3. Sequential loop with counter label: "Compacting {i+1} of {count}…"
  4. Call compaction on each instance (reuse `DiskTabViewModel.RunCompactionAsync` or inline logic)
  5. On cancel: stop queuing new compactions; already-started instance completes
  6. On completion: exit multi-select mode, clear all `IsSelected`
- [ ] Add bulk counter label UI to dashboard (visible during bulk compaction)
- [ ] Add Cancel button for bulk operation

**Acceptance** (B-01):
- [ ] Bulk compaction completes all selected instances sequentially
- [ ] Cancelling mid-way does not corrupt any instance
- [ ] Counter label updates correctly

### P2-3: Implement Export Instance Flow

**Req**: B-02-1 through B-02-3, B-02-9, Design Review #8

- [ ] Implement `ExportInstanceCommand` on `WslInstanceViewModel`:
  1. Check if instance is running → show auto-stop prompt (B-02-3, UX-03)
  2. Open `SaveFileDialog` pre-populated with `{InstanceName}-{yyyyMMdd}.tar` (B-02-2)
  3. If file exists, show overwrite confirmation
  4. Set `IsBusy = true`
  5. Show indeterminate `ProgressRing` + elapsed time counter (no progress callback available — per Design Review #8)
  6. Call `ExportInstanceAsync(name, destPath, force, ct)`
  7. On success: read file size from disk, show completion dialog with path and size
  8. On failure: `FormatAlertMessage(ex)`, clean up partial files (B-02-9)
  9. Set `IsBusy = false` in finally
- [ ] Export menu item disabled when instance is running + tooltip "Stop the instance before exporting" (B-02-3)

**Acceptance** (B-02):
- [ ] Exported TAR can be re-imported
- [ ] Attempting to export a running instance shows a stop prompt
- [ ] Progress indicator (elapsed time) updates during operation

### P2-4: Implement Import Instance Flow

**Req**: B-02-4 through B-02-8

- [ ] Create `ImportInstanceDialog` (inline dialog or modal window):
  - Instance name text field (required)
  - Install path folder picker (required)
  - Source TAR file picker (required)
  - Field-level validation error display
- [ ] Implement `ImportInstanceCommand` on `MainViewModel`:
  1. Open `ImportInstanceDialog`
  2. Validate instance name doesn't already exist (B-02-6) — field-level error
  3. Validate all 3 fields are filled
  4. On confirm:
     - Set global `IsBusy` (disable other toolbar ops) (B-02-7)
     - Show indeterminate `ProgressRing` + phase label
     - Call `ImportInstanceAsync(name, source, installPath, ct)`
     - On success: refresh instance list, select newly added instance (B-02-8)
     - On failure: `FormatAlertMessage(ex)`, ensure no partial files (B-02-9)
     - Clear `IsBusy`

**Acceptance** (B-02):
- [ ] Import with a duplicate name is blocked with an explanatory message
- [ ] After successful import, new instance appears in dashboard and is selected
- [ ] On failure, no partial files remain
