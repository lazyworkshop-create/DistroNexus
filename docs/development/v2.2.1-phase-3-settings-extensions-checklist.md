## Tasks

### P3-1: Implement WSL Global Configuration Editor UI

**Req**: E-01-1 through E-01-7

#### P3-1a: Create `WslConfigSectionView.xaml`

- [ ] Create `src/Client/DistroNexus.Desktop/Controls/WslConfigSectionView.xaml` + `.xaml.cs`
- [ ] Collapsible `ui:CardExpander` section at bottom of Settings page
- [ ] Host info display: total RAM, CPU count (from `GetHostSpecsAsync`)
- [ ] Form controls:
  - Memory: text field + MB/GB dropdown selector (E-01-3)
  - Processors: integer spinner, range 1 to host CPU count (E-01-3)
  - Swap: text field + MB/GB dropdown, 0 = disabled (E-01-3)
  - Localhost forwarding: toggle switch (E-01-3)
  - Networking mode: dropdown (NAT / mirrored / bridged / virtiofs) (E-01-3)
- [ ] Validation error labels under each field (E-01-4)
- [ ] Warning banner when memory > 80% of host RAM (E-01-5)
- [ ] **Save & Restart WSL** button (E-01-6)
- [ ] **Open Raw File** button (E-01-7)
- [ ] Use `{DynamicResource}` for all brushes

#### P3-1b: Create `WslConfigSectionViewModel.cs`

- [ ] Create `src/Client/DistroNexus.Desktop/ViewModels/WslConfigSectionViewModel.cs`
- [ ] Constructor receives: `IWslConfigService`, `IWslManagerService` (or `IWslCliRunner` for shutdown), `IDialogService`
- [ ] `LoadAsync()`:
  - Call `GetWslConfigAsync()` to populate form fields
  - Call `GetHostSpecsAsync()` to get host RAM and CPU count
- [ ] Validation logic (E-01-4):
  - Memory and swap: positive numbers
  - Processors: between 1 and host CPU count
  - Show field-level errors on invalid input
- [ ] `SaveAndRestartCommand`:
  1. Validate all fields
  2. If memory > 80% host RAM → show warning banner (allow proceed)
  3. Call `SetWslConfigAsync(config)` (E-01-8: must preserve unknown keys — see P3-3)
  4. Show confirm dialog: "Run wsl --shutdown to apply changes?"
  5. If confirmed: call `ShutdownWslAsync(ct)` (or `IWslCliRunner.RunAsync("--shutdown")`)
  6. Refresh dashboard
- [ ] `OpenRawFileCommand`: open `.wslconfig` in default text editor via `Process.Start`
- [ ] Error handling: `FormatAlertMessage` for all caught exceptions

#### P3-1c: Wire into `SettingsPage`

- [ ] Add `WslConfigSectionViewModel` as a property on `SettingsViewModel`
- [ ] Add `WslConfigSectionView` to `SettingsPage.xaml` (below existing cards)
- [ ] Wire lazy loading: call `LoadAsync` on section expand

**Acceptance** (E-01):
- [ ] Changes saved via UI are reflected in `.wslconfig` on disk
- [ ] Unknown keys present before editing are not removed
- [ ] Invalid input is rejected with field-level error
- [ ] After Restart WSL, `wsl -l -v` shows no running instances

### P3-2: Verify/Fix unknown INI key preservation in `WslConfigService`

**Req**: E-01-8, Design Review #6

- [ ] Inspect `WslConfigService.SetWslConfigAsync` implementation:
  - Does it read-modify-write the file, preserving unknown lines?
  - Or does it serialize only known `WslConfig` properties (destructive)?
- [ ] **If destructive**: implement one of:
  - **Option A**: Add `Dictionary<string, string> RawExtras` to `WslConfig` model; round-trip unknown keys
  - **Option B**: Read `.wslconfig` as raw text lines; only update known key-value pairs in-place
- [ ] Add unit test: write a `.wslconfig` with extra keys, call `SetWslConfigAsync`, verify extras preserved

**Acceptance**:
- [ ] A `.wslconfig` with custom keys like `guiApplications=true` retains those keys after a save
