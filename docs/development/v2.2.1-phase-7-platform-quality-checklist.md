### P7-1: Wire `WslEventWatcher.Start()` (E-07)

**Req**: F-01-1 through F-01-4, Design Review #1, #10

- [ ] **Call `_wslEventWatcher.Start()`** at the **end** of `LoadDataInBackgroundAsync()`, after the initial instance list has loaded
  - NOT in `InitializeAsync()` — this prevents data-race (Design Review #1)
- [ ] Move event subscription to the same location:
  ```csharp
  // At end of LoadDataInBackgroundAsync:
  _wslEventWatcher.CacheInvalidationRequested += OnCacheInvalidated;
  _wslEventWatcher.Start();
  ```
- [ ] Modify existing `OnCacheInvalidated` handler to set `IsAutoRefreshing`:
  ```csharp
  private async void OnCacheInvalidated(object? sender, EventArgs e)
  {
      IsAutoRefreshing = true;
      await Application.Current.Dispatcher.InvokeAsync(
          async () => await LoadInstancesAsync(CancellationToken.None));
      IsAutoRefreshing = false;
  }
  ```
- [ ] Verify watcher subscribes to both `wsl.exe` and `wslhost.exe` start/stop events (F-01-2)
- [ ] Verify 2-second debounce coalescing is functional (F-01-3)
- [ ] Wire the auto-refresh spinner in toolbar (created in Phase 1) to `IsAutoRefreshing` (F-01-4)
- [ ] Verify PowerShell `Cache.ps1` TTL-based 10-minute fallback still works (F-01-5)
- [ ] Verify `Get-DistroNexusCache` diagnostic cmdlet output (F-01-6)

**Acceptance** (F-01):
- [ ] Starting an instance from terminal causes UI to reflect new state within 3 seconds
- [ ] No UI freeze or jank during background refresh
- [ ] With WMI disabled, 10-minute TTL fallback still works

### P7-3: Unified Error Code Rollout (E-09)

**Req**: F-03-1 through F-03-6

- [ ] `WslManagerService.cs`
- [ ] `DockerIntegrationService.cs`
- [ ] `BackupService.cs`
- [ ] `NetworkService.cs`
- [ ] `TagService.cs`
- [ ] `WslConfigService.cs`
- [ ] `TemplateService.cs`
- [ ] `CatalogSourceManager.cs`

- Identify the correct specific error code from `DistroNexusErrorCode`
- Add new codes if necessary (document in P7-3e)
- Replace with typed exception

#### P7-3b: Desktop Layer — All error dialogs use `FormatAlertMessage` (F-03-2)

Audit all `catch` blocks in:

- [ ] `MainWindow.xaml.cs`
- [ ] `App.xaml.cs`
- [ ] `MainViewModel.cs`
- [ ] `SettingsViewModel.cs`
- [ ] `TemplatesViewModel.cs`
- [ ] `PackageManagerViewModel.cs`
- [ ] All new tab ViewModels (Phase 2–5)

Ensure pattern:
```csharp
catch (WslException ex) { ShowAlert(MainViewModel.FormatAlertMessage(ex)); }
catch (Exception ex) { ShowAlert(ex.Message); }
```

#### P7-3c: Copy Error Code button (F-03-3)

- [ ] Add a **Copy Error Code** link/button to the standard error dialog
- [ ] When clicked: copy `DN-{code:D4}` to clipboard
- [ ] Implementation options:
  - Extend `ConfirmDialog` with a `CopyCodeText` parameter
  - Or create a dedicated `ErrorDialog` UserControl
  - Or add a Hyperlink button inside the existing `ShowAlert` helper

#### P7-3d: NLog structured field (F-03-4)

- [ ] Update `nlog.config` to include error code in structured output:
  ```xml
  layout="${longdate}|${level}|${logger}|ErrorCode=${event-properties:item=ErrorCode}|${message}"
  ```
- [ ] At throw/catch sites, log the error code:
  ```csharp
  var logEvent = new LogEventInfo(LogLevel.Error, _logger.Name, ex.Message);
  logEvent.Properties["ErrorCode"] = (int)ex.ErrorCode;
  _logger.Log(logEvent);
  ```
  Or use structured logging:
  ```csharp
  _logger.Error(ex, "Operation failed. ErrorCode={ErrorCode}", (int)ex.ErrorCode);
  ```

#### P7-3e: PowerShell cmdlets `-ErrorId` (F-03-5)

- [ ] Audit all PS cmdlets for `Write-Error` calls
- [ ] Ensure each uses `-ErrorId "DistroNexus.<CodeName>"`:
  ```powershell
  Write-Error -Message $_.Exception.Message `
              -ErrorId "DistroNexus.$($_.Exception.ErrorCode)" `
              -Category OperationStopped `
              -TargetObject $InstanceName
  ```
- [ ] Add Pester tests verifying `-ErrorId` format:
  ```powershell

  ```
