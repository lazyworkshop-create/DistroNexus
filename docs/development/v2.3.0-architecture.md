# DistroNexus v2.3.0 Architecture Overview

## Boundaries

- `DistroNexus.Core` owns models, validation, versioned persistence, process contracts, previews, confirmation grants, redaction, and service implementations.
- `DistroNexus.Desktop` owns WPF views, localized resources, view models, dialogs, and dependency composition. It never reconstructs raw process output into business state.
- `DistroNexus.WorkspaceBridge` owns a line-delimited JSON automation boundary. It composes Core services and returns typed, redacted results; it does not permit arbitrary command execution.
- `src/PowerShell` owns thin public adapters. Mutations use `ShouldProcess` and call the bridge/Core contract rather than invoking WSL directly.

## Persistence and security

Application-owned JSON stores use schema versions, atomic writes, revisions, deterministic migrations and rejection of newer schemas. Legacy v2.2.1 settings, tags, backup schedules, templates, and instance registration fixtures remain readable. Secrets, private keys and personal paths are redacted from user-facing diagnostics.

## Health composition

Desktop and bridge health scans compose Core checks for platform capabilities, configuration, storage, backups, templates, integrations, networking, systemd, monitoring and WSLg. The bridge performs only read-only probes; preview/confirmation is required for repairs.

## External boundary

The repository does not prove real WSL/WSLg/USB/optional-runtime behavior, package identity, Store behavior or rollback. Those are release-owner acceptance gates, tracked in the v2.3 release evidence record.
