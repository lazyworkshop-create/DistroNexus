# v2.3.0 Elevated Helper Threat Model

## Scope

The unelevated desktop process may request narrowly scoped Windows Firewall rule creation or removal. It never receives a general administrator shell, executable path, command text, or password.

## Trust boundary and contract

The production `IFirewallOperationBroker` is a short-lived, product-signed helper launched only after a Core-generated preview is shown and explicitly confirmed. The helper accepts one versioned request over a named pipe restricted to the current user and Administrators, validates all fields again, performs one allow-listed operation, returns structured output, and exits. Rule creation accepts only protocol, direction, port, known profiles, an IP/CIDR or `LocalSubnet` remote scope, and a fully-qualified executable scope. Removal accepts only deterministic `DistroNexus-` rule identities.

## Threats and controls

| Threat | Control |
|---|---|
| Arbitrary command/elevation | No command-string field; fixed operation enum and typed values only. |
| Preview substitution/replay | Preview has a one-time server-held token bound to its semantic rule fields. |
| Third-party firewall modification | Removal rejects identifiers outside the deterministic DistroNexus namespace. |
| Path or scope injection | Core and helper reject newline/NUL scopes; helper repeats full validation. |
| Silent firewall weakening | UI shows direction, protocol, port, profile, remote and executable scope, then requires confirmation. |
| Helper impersonation | Release acceptance verifies signed helper identity and named-pipe ACL. |

## Local evidence and external gate

This repository uses `GuardedFirewallOperationBroker`, which validates and previews but returns `ElevatedHelperUnavailable` rather than mutating the host. Signed-helper identity, UAC publisher, named-pipe ACL, and actual rule create/remove are privileged release/UAT gates.
