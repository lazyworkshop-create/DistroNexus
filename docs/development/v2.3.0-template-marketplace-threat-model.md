# v2.3.0 Template Marketplace Threat Model

## Scope

This document covers marketplace sources, manifest v2, artifact download/cache, trust decisions, and update review. It does not authorize remote template execution, catalog publishing, or any network write.

## Assets and boundaries

- A source URL and publisher fingerprint are distinct identity inputs; a display name is never an authority.
- A remote catalog and artifact are untrusted until their manifest is validated, the artifact hash is verified, and the user has made the scoped trust decision.
- The content-addressed artifact cache and its known-good pointer are local security assets.

## Controls

| Threat | Control |
|---|---|
| Source substitution or downgrade | HTTPS is required for remote sources by default; local/insecure development sources require explicit confirmation. |
| Artifact tampering | SHA-256 is mandatory before extraction or selection. A mismatch fails closed. |
| Publisher-name spoofing | Trust is stored by normalized source URL plus publisher key fingerprint. |
| Malicious archive | Entries are rejected when rooted or traversal-like; extraction is rooted and archive/expanded size limits are enforced. |
| Silent privilege expansion | Script hash, publisher, or newly declared capability changes require review. |
| Failed update | Existing known-good artifacts remain untouched until the candidate has been verified and safely extracted. |
| High-impact execution | Templates declaring root, filesystem-path, or service-change capability return a recovery-point recommendation. No recovery point is created implicitly. |
| Legacy remote content | Remote manifest v1 is rejected and never forwarded to execution. |
