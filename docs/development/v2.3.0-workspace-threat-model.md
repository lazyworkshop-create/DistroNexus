# v2.3.0 Workspace Threat Model

## Boundary

Imported definitions and their command text are untrusted data. A workspace can invoke local Windows tools and WSL commands, but it never crosses the elevation boundary.

## Controls

- Import parsing has a 512 KiB limit and validates stable IDs, action graph, URLs, paths, and control characters.
- Imports are always persisted as `Untrusted`; edits do not change that state. Explicit trust is revision-bound.
- Preview tokens are random, short-lived, single-use, and bind workspace ID plus revision. Launch revalidates the durable definition and instance.
- Actions use `ProcessStartInfo.ArgumentList` through `IProcessRunner`; no workspace field is concatenated into a command line.
- Shell scripts are a separate action type, rendered fully in preview, and require trust. They are never used for discovery or preflight.
- Browser actions allow only HTTPS; Linux paths reject traversal and control characters; systemd and compose action validation remains typed.
- Parallel execution is allowed only for a group whose actions declare `SafeForParallel` and have no dependency. Groups otherwise execute in order.
- Failure never triggers unsafe automatic rollback. Close policy remains opt-in and requires a dedicated preview/confirmation path.

## Remaining external evidence

Verify real Terminal, VS Code, browser, WSL systemd/compose, and Windows shortcut behavior on supported environments before enabling release claims.
