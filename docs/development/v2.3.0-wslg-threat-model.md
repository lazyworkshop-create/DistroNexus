# WSLg application discovery threat model

S10 treats `.desktop` files and their icon references as untrusted Linux-side input. Discovery only reads files from approved application roots and never invokes an entry's `Exec` value. The parser rejects control characters, Windows executables, path traversal, remote icon URLs, terminal/hidden/no-display entries, unknown field codes, and malformed quoting. It produces an executable plus argument list; launch invokes `wsl.exe --distribution <name> --exec <executable> <arguments>` with `UseShellExecute=false`. No command is routed through cmd, PowerShell, sh, or an interpolated command line.

The local pin store contains opaque SHA-256 entry IDs only. Icons are intentionally not fetched from remote locations; any decoded local bytes enter a 256-entry/16 MiB LRU cache only after root and 1 MiB limits pass. Real WSLg display/audio and graphical-launch validation remain opt-in external UAT.
