## 四、AI 协同编程的关键模式

### 4.1 文档驱动开发 (Documentation-Driven Development)

这是本项目最显著的 AI 协同模式。AI 在每个阶段都先产出文档, 再编写代码:

```
需求文档 → 任务分解清单 → 代码实现 → 测试文档 → 验收清单 → 归档
```

**计划三件套**: 项目强制要求在复杂任务前创建：
- `task_plan.md` — 任务分解与状态跟踪
- `findings.md` — 调研结论记录
- `progress.md` — 进度日志

**文档生命周期管理**:
- 活跃文档在 `docs/architecture/` 和 `docs/development/` 中随代码更新
- 完成的计划文档自动归档到 `docs/archive/{year}/{month}/{yyyymmdd}_{topic}/`
- 45 份归档文档证明了严格的文档生命周期管理

### 4.2 Copilot 指令系统 (`.github/copilot-instructions.md`)

项目通过一份结构化的指令文件来"训练" AI 保持一致的编码风格和工程规范:

- **语言规定**: 所有代码/注释/内部文档必须英文
- **命名约定**: C# PascalCase, PowerShell Verb-Noun, commits 遵守 Conventional Commits
- **编码模式**: MVVM, async/await, 构造器注入 DI
- **错误处理**: 先捕获特定异常, 全量记录日志, UI 友好提示
- **计划规则**: 3 步以上任务必须先创建计划文档

这份指令文件本身也经历了多次迭代 (从中文到英文, 从简单到结构化), 反映了人类开发者与 AI 之间"对齐协议"的演进。

### 4.3 技术栈重写: AI 执行, 人类决策

v1 → v2 的技术栈重写是 AI 协同编程的极端案例:

| 维度 | v1.0 | v2.0 |
|------|------|------|
| 语言 | Go | C# (.NET 10) |
| UI 框架 | Fyne (跨平台) | WPF (Windows 原生) |
| 架构 | 单体脚本 | MVVM + DI + 分层 |
| 后端 | 独立 PS 脚本 | PowerShell 模块 (15 Cmdlets) |
| 测试 | 无 | xUnit + Moq + Pester |
| 构建 | 手动 | CI/CD 自动化 |

**重写在 1 月 27 日一天内完成了核心骨架**: PowerShell 模块 → .NET 解决方案 → Core 层 → WPF 层，展现了 AI 在大规模代码生成方面的惊人效率。

### 4.4 迭代式问题修复

从 git 日志可以观察到典型的 AI 调试模式:
- CI 流水线调试: 6 个连续 fix 提交 (1/24 22:43 - 23:52) 修复 runner、路径、权限等问题
- 启动冻结问题: 多个归档文档记录了从诊断到解决的完整过程
  - `startup-freeze-fix-report` → `startup-fix-test-checklist` → `startup-skip-settings-solution`
  - 最终通过 SettingsService 同步化重构解决
- 编译错误修复: 跨 XAML 和 C# 的资源引用一致性修复

### 4.5 自动化测试的 AI 方法论

AI 不仅编写测试代码, 还设计了完整的测试方法论:

1. **分层测试策略**: 单元测试 (Moq) → 集成测试 (WPF-PS 桥接) → 端到端自动化
2. **模板自动化套件**: 自主设计的 Pass/Fail/Blocked 三状态分类系统
3. **测试证据归档**: 测试结果 XML + JSON manifest + Markdown 总结持久化
4. **安全防护**: CI 中默认禁用真实 WSL 测试, 需显式覆盖

### 7.1 AI 协同编程的效率倍增

尽管 AI 完成了几乎所有执行工作, 但以下关键决策仍由人类做出:
