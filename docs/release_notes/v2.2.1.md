# DistroNexus v2.2.1 Release Notes

**Release Date:** 2026-03-22

## Overview

DistroNexus v2.2.1 is the **Platform Quality & Completion** patch release for v2.2.0. It closes all
remaining architectural gaps from the deep-instance-management feature set: structured error codes
throughout the application, a user-visible "Copy error code" action in every error dialog,
WMI event-watcher lifecycle fixes, native registry reads replacing secondary PowerShell process
invocations, and full localization of new UI strings.

No new end-user features are introduced. All changes improve reliability, debuggability, and
consistency.

## Improvements

### Error Code Coverage

- `DistroNexusErrorCode` enum expanded with five new codes that complete coverage of all operation
  failure paths:
  - `TooManyTags (1005)` — tag limit exceeded on an instance.
  - `ScheduleNotFound (4005)` — referenced backup schedule does not exist in Task Scheduler.
  - `TemplateNotFound (6001)` — requested template ID is not in the catalog.
  - `TemplateScriptFailed (6002)` — template post-install script exited with non-zero.
  - `PowerShellModuleUnavailable (9004)` — PowerShell module path cannot be resolved at runtime.
- New **6xxx Templates** error-code category added to the reference documentation.
- All PowerShell public cmdlets now include `-ErrorId "DistroNexus.<Code>"` on every `Write-Error`
  call, making errors machine-readable in PowerShell error streams and standardised for C# callers.

### User-Visible Structured Error Dialogs

- All error alert dialogs now consistently display a `[DN-XXXX]` prefix when a `WslOperationException`
  is thrown — powered by the new `MainViewModel.FormatAlertMessage()` helper adopted across all
  ViewModel catch blocks.
- When an error dialog contains a `[DN-XXXX]` code, a **"Copy error code"** hyperlink appears below
  the message so users can immediately copy the structured code when reporting issues.
- NLog JSON and console layouts now include an `errorCode` field, enabling structured triage from
  log files without parsing free-text error messages.

### Architecture

- **WMI Event-Watcher lifecycle fixed**: `WslEventWatcher.Stop()` / `Dispose()` is now correctly
  called from both `WslManagerService.Dispose()` and `MainViewModel.Dispose()`. Previously the WMI
  subscription could outlive the application window, holding a background thread.
- **`WslEventWatcher.Start()` deferred**: the watcher now starts only after the initial instance-list
  load completes, eliminating a race condition where the first WMI event could trigger a refresh
  before the UI was populated.
- **Native registry reads**: `WslManagerService.RenameInstanceAsync` no longer spawns a secondary
  PowerShell process to resolve the instance install path. The new `GetInstallPathFromRegistry`
  helper mirrors the existing `GetVhdxSizeBytes` pattern and reads directly from
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss`.
- Dead code removal: unreachable `GetInstancesInlineAsync` method and unused `LxssRegistryPath`
  constant removed from `WslManagerService`.

### Localization

- All remaining hardcoded English strings in ViewModels and XAML views replaced with `Resources.resx`
  keys that have corresponding zh-CN translations:
  - `TitleBackupFailure`, `ErrorBackupFailedForInstance` — backup notification dialog.
  - `TitleInvalidModulePath`, `ErrorInvalidModulePath` — settings module-path validation.
  - `ActionApply`, `ActionExport`, `ActionImport`, `BadgeOfficial` — Templates page UI.
  - `ErrorCopyCode` — error dialog "Copy error code" hyperlink label.
- `TemplatesPage.xaml` updated to use `{lex:Loc ...}` bindings throughout.

## Bug Fixes

- Fixed three `WslManagerService.GetInstancesAsync` catch blocks that incorrectly raised
  `UnknownError` when the PowerShell module path was missing; now correctly raise
  `PowerShellModuleUnavailable (9004)`.

## Testing

- Unit test suite: **96 passing**, 3 skipped (STA dialog tests), 0 failures.
- Build: **0 errors**, 17 pre-existing platform-annotation warnings.
