# DistroNexus v2.2.1 发行说明

**发布日期：** 2026-03-22

## 概述

DistroNexus v2.2.1 是 v2.2.0 的**平台质量与完善**补丁版本。本次发布填补了深度实例管理功能集中所有遗留的架构空白：在整个应用程序中引入结构化错误代码、在每个错误对话框中提供"复制错误代码"操作、修复 WMI 事件监视器生命周期问题、用原生注册表读取替换次级 PowerShell 进程调用，并完成对所有新增 UI 字符串的本地化处理。

本版本不引入任何新的终端用户功能，所有变更均旨在提升可靠性、可调试性和一致性。

## 改进

### 错误代码覆盖

- 扩展 `DistroNexusErrorCode` 枚举，新增五个涵盖所有操作失败路径的错误代码：
  - `TooManyTags (1005)` — 实例标签数量超出上限。
  - `ScheduleNotFound (4005)` — 任务计划程序中不存在所引用的备份计划。
  - `TemplateNotFound (6001)` — 目录中不存在所请求的模板 ID。
  - `TemplateScriptFailed (6002)` — 模板安装后脚本以非零状态退出。
  - `PowerShellModuleUnavailable (9004)` — 运行时无法解析 PowerShell 模块路径。
- 在参考文档中新增 **6xxx 模板**错误代码分类。
- 所有 PowerShell 公开命令的每个 `Write-Error` 调用均已加入 `-ErrorId "DistroNexus.<Code>"`，使错误在 PowerShell 错误流中可被机器读取，并为 C# 调用方提供统一规范。

### 用户可见的结构化错误对话框

- 所有错误提示对话框在抛出 `WslOperationException` 时，现在会一致显示 `[DN-XXXX]` 前缀——由新增的 `MainViewModel.FormatAlertMessage()` 帮助方法驱动，已在所有 ViewModel 的 catch 块中采用。
- 当错误对话框包含 `[DN-XXXX]` 代码时，消息下方会出现**"复制错误代码"**超链接，方便用户在报告问题时立即复制结构化代码。
- NLog 的 JSON 和控制台布局现已包含 `errorCode` 字段，无需解析自由文本错误消息即可从日志文件中进行结构化分类。

### 架构

- **修复 WMI 事件监视器生命周期**：`WslEventWatcher.Stop()` / `Dispose()` 现在可从 `WslManagerService.Dispose()` 和 `MainViewModel.Dispose()` 两个释放路径正确调用。此前 WMI 订阅可能在应用程序窗口关闭后仍持有后台线程。
- **延迟启动 `WslEventWatcher.Start()`**：监视器现在仅在初始实例列表加载完成后才启动，消除了第一个 WMI 事件可能在 UI 填充完成前触发刷新的竞态条件。
- **原生注册表读取**：`WslManagerService.RenameInstanceAsync` 不再启动次级 PowerShell 进程来解析实例安装路径。新增的 `GetInstallPathFromRegistry` 帮助方法沿用现有的 `GetVhdxSizeBytes` 模式，直接从 `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss` 读取。
- 死代码清理：从 `WslManagerService` 中移除不可达的 `GetInstancesInlineAsync` 方法和未使用的 `LxssRegistryPath` 常量。

### 本地化

- 将 ViewModel 和 XAML 视图中所有剩余的硬编码英文字符串替换为具有对应简中翻译的 `Resources.resx` 键：
  - `TitleBackupFailure`、`ErrorBackupFailedForInstance` — 备份通知对话框。
  - `TitleInvalidModulePath`、`ErrorInvalidModulePath` — 设置模块路径验证。
  - `ActionApply`、`ActionExport`、`ActionImport`、`BadgeOfficial` — 模板页面 UI。
  - `ErrorCopyCode` — 错误对话框"复制错误代码"超链接标签。
- `TemplatesPage.xaml` 已全面更新为使用 `{lex:Loc ...}` 绑定。

## 缺陷修复

- 修复 `WslManagerService.GetInstancesAsync` 中三处 catch 块在 PowerShell 模块路径缺失时错误地抛出 `UnknownError` 的问题；现已正确抛出 `PowerShellModuleUnavailable (9004)`。
