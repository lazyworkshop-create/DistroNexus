## 1. Overview

v2.2.1 is a completion release that wires already-built Core service capabilities into the desktop GUI.  
The design adds **one new dialog** (`InstanceDetailDialog`), **three toolbar controls** (multi-select toggle, Import button, auto-refresh indicator), **a tag filter bar**, and **two new SettingsPage sections** — all without restructuring existing navigation or page routing.

Key design constraints carried over from the requirements:

- No new product directions; only surface existing backends.
- All new XAML must use `WindowBackdropType="Mica"` and `{DynamicResource}` brushes.
- All display strings routed through `Properties/Resources.resx` (en-US + zh-CN).
- All error dialogs must call `MainViewModel.FormatAlertMessage(ex)`.

#### 2.3.1 Tag Filter Bar

Inserted between the toolbar row and the instance list:

```
┌───────────────────────────────────────────────────────────┐
```

- `CompactSelectedCommand` on `MainViewModel` collects `Instances.Where(i => i.IsSelected)` and runs sequential compaction with an overall counter label.
- Exiting multi-select mode clears all selections.

### 3.3 Data & Command Flow

#### 3.3.1 Opening InstanceDetailDialog

```
User clicks "Details…" in MoreButton menu
  → WslInstanceViewModel.OpenDetailsCommand
      → new InstanceDetailViewModel(instance, services…)
          → new InstanceDetailDialog(vm)
              → dialog.ShowDialog()
  (Dialog ViewModel initialises all tab VMs lazily on tab selection via OnTabChanged)
```

Lazy tab initialisation avoids firing 5 service calls simultaneously on dialog open. Each tab VM exposes an `InitializeAsync()` method called when its tab gains focus for the first time.

#### 3.3.2 Compact Disk Flow (single instance)

> **Note**: `IWslManagerService.CompactInstanceAsync` returns `Task` (void). The reclaimable-space estimate is derived by parsing progress callback messages during the `whatIf` run. Actual disk sizes before and after compaction are read via `GetInstanceDiskSizeAsync`.

```
DiskTabViewModel.CompactDiskCommand
  → // whatIf run: parse progress messages to extract reclaimable size estimate
  → estimatedReclaim = 0L
  → whatIfProgress = new Progress<(double, string)>(p =>
      { /* parse "Reclaimable: X bytes" pattern from p.Message → set estimatedReclaim */ })
  → await IWslManagerService.CompactInstanceAsync(name, whatIfProgress, whatIf: true, ct)
  → ConfirmDialog.ShowAsync(FormatBytes(estimatedReclaim), autoStopWarning)
  → if confirmed:
      Instance.IsBusy = true
      beforeSize = await IWslManagerService.GetInstanceDiskSizeAsync(name, ct)
      progress = new Progress<(double, string)>(p => PhaseText = p.Message)
      await IWslManagerService.CompactInstanceAsync(name, progress, whatIf: false, ct)
      afterSize = await IWslManagerService.GetInstanceDiskSizeAsync(name, ct)
      Instance.IsBusy = false
      show result panel (beforeSize → afterSize, saved = beforeSize - afterSize)
  → on WslException/WslOperationException:
      Instance.IsBusy = false
      MessageBox(FormatAlertMessage(ex))
```

#### 3.3.3 Bulk Compact Flow

```
MainViewModel.CompactSelectedCommand
  selected = Instances.Where(i => i.IsSelected).ToList()
  cts = new CancellationTokenSource()
  for i, inst in selected:
      BulkCounterLabel = $"Compacting {i+1} of {selected.Count}…"
      if cts.IsCancellationRequested && inst not yet started: break
      await DiskTabViewModel.RunCompactionAsync(inst, cts.Token)
  IsMultiSelectMode = false
  Instances.ForEach(i => i.IsSelected = false)
```

The **Cancel** button sets `cts.Cancel()`. Already-running instances complete before stopping.

#### 3.3.4 Import Instance Flow

```
MainViewModel.ImportInstanceCommand
  → ImportInstanceDialog.ShowAsync()   (inline dialog, not a tab)
      collects: Name, InstallPath, SourceTar
      validates Name uniqueness (local check against Instances)
      → if invalid: field error, stay open
  → if confirmed:
      IsBusy (global, disables other toolbar ops)
      await IWslManagerService.ImportInstanceAsync(name, source, installPath, ct)
      await RefreshCommand
      select newly added instance
  → on failure: FormatAlertMessage(ex), ensure partial files cleaned up
```

#### 3.3.4b Export Instance Flow

> **Important**: `IWslManagerService.ExportInstanceAsync` has no progress callback. Use an indeterminate spinner with an elapsed-time counter.

```
WslInstanceViewModel.ExportInstanceCommand  (context menu "Export Instance…")
  → ExportDialog.ShowAsync()
      collects: DestinationPath (pre-filled: Desktop\{name}.tar)
               [Force overwrite] checkbox
      → if file exists && !force: show overwrite confirmation
  → if confirmed:
      IsBusy = true
      PhaseText = "Exporting…"
      show indeterminate ProgressRing + elapsed timer ("00:01:23 elapsed")
      await IWslManagerService.ExportInstanceAsync(name, destPath, force, ct)
      IsBusy = false
      exportedSize = new FileInfo(destPath).Length  // read after completion
      show completion panel: "Exported to {path} ({exportedSize})"
  → on failure: FormatAlertMessage(ex), IsBusy = false
```

#### 3.3.5 WSL Config Save Flow

```
WslConfigSectionViewModel.SaveAndRestartCommand
  → validate all fields (field-level error messages)
  → if memory > 0.8 * hostRam: show warning banner but allow proceed
  → await IWslConfigService.SetWslConfigAsync(config)
  → ConfirmDialog("Run wsl --shutdown to apply changes?")
  → if confirmed:
      // IWslManagerService has no ShutdownAsync method.
      // Option A (preferred): call IWslCliRunner.RunAsync("--shutdown", ct) directly.
      // Option B: add a thin ShutdownWslAsync() wrapper to IWslManagerService.
      await _wslCliRunner.RunAsync("--shutdown", ct)
  → await RefreshCommand (instance list will be empty / stopped)
```

> **`WslConfig` unknown-key preservation**: The current `WslConfig` model has only 5 known properties and no `RawExtras` field. If the user's `.wslconfig` contains custom keys beyond those 5, they will be silently dropped on save. The implementation must either: (a) add a `Dictionary<string, string> RawExtras` property to `WslConfig` to preserve unknown keys in a round-trip, or (b) read `.wslconfig` as raw text and only update the 5 known key-value pairs in-place, leaving unknown lines untouched.

#### 3.3.6 Tag Operations Flow

```
# Add tag from card inline popover
WslInstanceViewModel.AddTagCommand(tagText)
  → await ITagService.AddTagAsync(instanceName, tagText)
  → Tags.Add(tagText)
  → MainViewModel.AvailableTags refresh (add if new)

# Filter by tag
MainViewModel.TagFilterChangedCommand
  → activeFilters = AvailableTags.Where(t => t.IsSelected).ToList()
  → // ObservableCollection<T> has no Filter property; use ICollectionView:
  → InstancesView.Filter = inst =>
        !activeFilters.Any() ||
        activeFilters.All(f => ((WslInstanceViewModel)inst).Tags.Contains(f.Name))
  → InstancesView.Refresh()

# Group by tag
MainViewModel.ToggleGroupByTagCommand
  → InstancesView.GroupDescriptions.Clear() (or Add new PropertyGroupDescription)
  // Note: multi-tag grouping is non-trivial; Phase 6 may ship single-tag-primary grouping only.
```

```csharp
public ICollectionView InstancesView { get; }

InstancesView = CollectionViewSource.GetDefaultView(Instances);
```

The dashboard `ItemsControl` binds to `InstancesView` instead of `Instances`.

### 3.4 Startup Wiring (F-1)

Currently `WslEventWatcher` is constructed and subscribed to in `MainViewModel` but `Start()` is never called.

**Change**: `_wslEventWatcher.Start()` must be called at the **end** of `MainViewModel.LoadDataInBackgroundAsync()`, after the initial instance list has loaded — **not** in `InitializeAsync()`. Starting the watcher before data is loaded can cause `OnCacheInvalidated` to fire before the UI collection is populated.

```csharp
// At the end of LoadDataInBackgroundAsync(), after Instances are populated:
_wslEventWatcher.CacheInvalidationRequested += OnCacheInvalidated;
_wslEventWatcher.Start();
```

**`OnCacheInvalidated` modification** — this handler already exists in `MainViewModel`. The only change required is wrapping the existing refresh call with `IsAutoRefreshing`:

```csharp
// Existing handler — add the two IsAutoRefreshing lines (marked NEW):
private async void OnCacheInvalidated(object? sender, EventArgs e)
{
    IsAutoRefreshing = true;      // NEW — shows the toolbar spinner
    await RefreshCoreAsync();     // already exists
    IsAutoRefreshing = false;     // NEW
}
```

The 2-second debounce inside `WslEventWatcher` coalesces rapid WSL process start/stop events before firing. This must be validated via unit test with a mock `IWslEventWatcher`.

`IsAutoRefreshing` drives a small `ui:ProgressRing` (16 px, `IsIndeterminate="True"`) in the toolbar right group, visible only when true. The spinner does not block UI interaction.

### 3.5 PowerShell Service Decoupling (F-2)

**Status — partially complete**: `WslManagerService.GetInstancesNativeAsync` (E-08 Phase 1) already uses `Microsoft.Win32.RegistryKey.OpenBaseKey` directly for VHDX size lookup and path resolution (via the private `GetVhdxSizeBytes` method). No new `IRegistryReader` interface is needed or planned.

**Remaining Phase 3 work**: Audit `WslManagerService` for any remaining PowerShell scripts that query the `Lxss` registry path. If found, replace them following the already-established pattern in `GetVhdxSizeBytes`:

```csharp
// Existing pattern — follow this, do NOT introduce a new interface:
using var hive = Microsoft.Win32.RegistryKey.OpenBaseKey(
    Microsoft.Win32.RegistryHive.CurrentUser,
    Microsoft.Win32.RegistryView.Registry64);
using var lxss = hive.OpenSubKey(@"Software\Microsoft\Windows\CurrentVersion\Lxss");
```

**Scope restriction** — `IPowerShellService` is retired from `WslManagerService` for registry read operations. It remains injected only into paths that genuinely require PowerShell:
- `ITemplateService` (template script execution)
- `IWslManagerService.SetCredentialsAsync` (PAM/shadow interaction)
- `IWslManagerService.CompactInstanceAsync` (delegates to `Compact-DistroNexusInstance` PS cmdlet)

**Unit test requirement**: New `WslManagerService` tests must mock `IWslCliRunner` (fake `wsl.exe` stdout) and use in-process filesystem fakes for VHDX path resolution — no real processes or registry access in tests. There is **no** `IRegistryReader` interface; test the `GetVhdxSizeBytes` path by controlling the filesystem layout in the test environment.

### 3.6 Unified Error Code Rollout (F-3)

#### 3.6.1 Service Layer (`DistroNexus.Core`)

All `throw` statements in services must be wrapped:

```csharp
// Pattern for new throw sites:
throw new WslOperationException(
    instanceName,
    DistroNexusErrorCode.CompactionFailed,  // specific code
    "Failed to compact VHDX",
    innerException);
```

Services to audit: `WslManagerService`, `DockerIntegrationService`, `BackupService`, `NetworkService`, `TagService`, `WslConfigService`, `TemplateService`, `CatalogSourceManager`.

> **`WslOperationTimeoutException` fix**: All 3 constructors of `WslOperationTimeoutException` currently hardcode `DistroNexusErrorCode.UnknownError`. A dedicated `DistroNexusErrorCode.OperationTimeout` value must be added to the enum, and the constructors updated to use it instead.

#### 3.6.2 Desktop Layer (ViewModels)

All `catch` blocks in ViewModels must end with a call to the existing `ShowAlert` mechanism. The project currently has no `IDialogService`; the standard pattern used in `MainViewModel` is:

```csharp
catch (WslException ex)
{
    ShowAlert(MainViewModel.FormatAlertMessage(ex));
}
catch (Exception ex)
{
    ShowAlert(ex.Message);  // non-typed fallback
}
```

> **For new tab ViewModels** that lack direct access to `ShowAlert`: introduce a minimal `IDialogService` interface injected via constructor, backed by the existing `ContentDialog` / `MessageBox` implementation. Wire it in DI. Do not add it globally until the interface design is agreed upon.

#### 3.6.3 Copy Error Code Button

`FormatAlertMessage` produces a string like `[DN-1001] Compaction failed: ...`.  
The error dialog adds a **Copy Error Code** hyperlink button:

```csharp
// In the error MessageBox helper:
if (errorCode != null)
    CopyCodeButton.Click += () => Clipboard.SetText($"DN-{(int)errorCode:D4}");
```

Implementation: Extract the error dialog into a reusable `ErrorDialog` UserControl or extend `ConfirmDialog` with a `CopyCodeText` parameter.

#### 3.6.4 NLog Structured Field

In `nlog.config`, add the error code as a structured layout renderer:

```xml
<target name="file" ...
    layout="${longdate}|${level}|${logger}|ErrorCode=${event-properties:item=ErrorCode}|${message}" />
```

At throw/catch sites:
```csharp
_logger.Error(ex, "Compaction failed. {@ErrorCode}", ex.ErrorCode);
// or via LogEventInfo:
logEvent.Properties["ErrorCode"] = (int)ex.ErrorCode;
```

#### 3.6.5 PowerShell Cmdlets

Each PS cmdlet error path:

```powershell
Write-Error -Message $_.Exception.Message `
            -ErrorId "DistroNexus.$($_.Exception.ErrorCode)" `
            -Category OperationStopped `
            -TargetObject $InstanceName
```

### 3.7 Localization Strategy

All new display strings must be added to `Properties/Resources.resx` before any corresponding UI is merged. The naming convention follows the existing pattern:

```
ResourceKey = <FeatureArea>_<ElementRole>
e.g. DiskTab_CompactDisk        = "Compact Disk"
     DiskTab_CompactConfirm     = "Ubuntu-22.04 will stop temporarily. Reclaim approximately {0}?"
     NetworkTab_NoInstanceIP    = "Start the instance to view network information"
     BackupTab_FrequencyDaily   = "Daily"
```

Placeholders use `{0}`, `{1}` format string convention, resolved via `string.Format` or `lex:Loc` with `FormatSegment`.

A corresponding `Resources.zh-CN.resx` entry must exist for every key before merge (even if it is a temporary machine-translated placeholder tagged with `<!-- TODO: review -->`).
