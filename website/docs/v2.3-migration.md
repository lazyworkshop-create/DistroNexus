# v2.3.0 release candidate migration

v2.3.0 preserves existing distributions, settings, tags, backups, local templates, and recorded instance registrations from v2.2.1. New capability data is stored in versioned files under the DistroNexus application-data root and is written atomically.

The first v2.3 write may wrap a legacy JSON document in a versioned envelope. Existing tag data remains inside the settings payload and unknown settings remain preserved. A file with a newer schema is opened read-only by the compatible code path: do not overwrite it with an older application version.

Before upgrading, copy the DistroNexus application-data directory using your normal Windows backup procedure. Do not edit recovery journals, marketplace artifacts, or workspace records while DistroNexus is running. If an upgrade is interrupted, keep the original files and use the diagnostic report rather than deleting state.

Remote templates and imported workspaces are deliberately untrusted until reviewed. Upgrading does not start WSL, change a distribution configuration, enable Windows features, install optional dependencies, or modify USB devices.

This documentation describes a release candidate. The supported Windows/WSL matrix, optional dependency matrix, signed package, Store behavior, and rollback rehearsal are release gates still awaiting authorized external evidence.
