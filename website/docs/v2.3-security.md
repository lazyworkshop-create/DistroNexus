# v2.3.0 security and troubleshooting

## Trust boundaries

Remote template catalogs, template artifacts, workspace imports, Linux application metadata, and container output are untrusted input. DistroNexus validates manifests, hashes and declared paths before an action is authorized. A template review is explicit and bound to the selected manifest; a changed artifact must be reviewed again.

The application does not expose arbitrary elevated commands. USB operations use a bounded protocol, and configuration, recovery, service, workspace, and marketplace mutations use previews and confirmation tokens. `-WhatIf` in the PowerShell module does not issue a mutation request.

## Command reference

Use `Get-Command -Module DistroNexus` for the installed module's authoritative list. v2.3 adds `Get-DistroNexusCapability`, `Invoke-DistroNexusHealthScan`, recovery-point commands, monitoring snapshots, systemd previews/actions, WSLg discovery/launch, container status, and trusted-template marketplace commands.

For a state-changing operation, request its preview first, inspect the returned effects, then run the corresponding action with confirmation. Do not copy preview tokens into logs or scripts; they are short-lived and one-shot.

## Troubleshooting

- If a capability is unavailable, inspect its stable reason code with `Get-DistroNexusCapability`; do not enable Windows features from a troubleshooting script.
- The automation bridge composes the same concrete Core checks for global and distribution configuration, backups, templates, monitoring, WSLg, and the other Health Center categories. It uses a read-only PowerShell adapter, so a health scan never executes repair, backup, template, or monitoring mutations; use a preview plus explicit confirmation for a state-changing action.
- If a template action is blocked, refresh the catalog and review its manifest, script diff, publisher and artifact hash again. Do not bypass trust using a URL change.
- If recovery reports manual recovery required, retain the operation journal and compare the target with the actual WSL registration before attempting cleanup.

## Privacy and diagnostics

Diagnostic output is redacted before it is presented or exported. Remove secrets, personal paths, tokens and private keys from any report before sharing it. Never add credentials, signing material or private paths to templates, workspace definitions, command arguments or issue reports.
